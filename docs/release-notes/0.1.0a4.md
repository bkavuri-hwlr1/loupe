# Loupe 0.1.0a4

This prerelease brings Wave 12 to Homebrew installations: proposals and
published changes can be exported as patches or bundles, scripts can switch a
conversation's workspace, sessions notice outside edits to more of the files
they read, and dependency rebuilds can reuse downloads. Isolated mode's
admission limits also rise, but a
[known limit](#known-limit-above-20000-source-paths) still stops checkouts
above 20,000 source paths from working for long.

## Before upgrading

Finish active tasks. Take a backup if you want a rollback point, exit open
Loupe terminals, and **stop every profile's daemon before upgrading**:

```sh
loupe db backup
loupe daemon stop
HOMEBREW_NO_INSTALL_CLEANUP=1 brew update
HOMEBREW_NO_INSTALL_CLEANUP=1 brew upgrade loupe
```

Repeat the backup and stop commands with `loupe --profile NAME` for each
profile you use. A daemon-unavailable message from `daemon stop` means that
profile is already stopped. `HOMEBREW_NO_INSTALL_CLEANUP=1` keeps Homebrew from
removing an interpreter that a daemon you missed still uses. The next
conversation starts the upgraded daemon.

The first start adds one table for exports (migration 34) and trims each
session's advisory outside-edit registrations to its newest 20,000. Session
history, proposals and publication records are not rewritten. Open
conversations, including isolated ones with a private worktree, resume as they
were. Do not reopen an upgraded profile with an older binary.

Coming from 0.1.0a2 or earlier? Read the
[0.1.0a3 notes](0.1.0a3.md) first. Their upgrade steps still apply: older
daemons ignore the cross-profile checkout lock, and 0.1.0a2 has no
`loupe db backup`.

## What changes

- **Export changes as files:** `loupe change export ID --to DEST` writes a held
  proposal, a staged candidate or a published batch to a new file, without
  publishing it again or creating a commit. The default `--format patch` is a
  Git binary patch for `git apply` on the exact base, and keeps binary files,
  executable modes and symlinks. `--format bundle` writes one JSON file with
  exact before and after identities and SHA-256 addressed bodies. An export
  never overwrites a file, needs `--into-checkout` to write inside a checkout,
  and refuses runtime files and source that holds recognized secrets. A crash
  leaves either no file or the complete file; retry with the same `--intent
  ID`. The destination's filesystem must support hard links: exFAT, FAT and
  some network shares are refused with that reason and leave nothing behind.
  Work from before the upgrade can be exported too. See
  [source exports](../isolated-workspaces.md#export-source-changes).
- **Switch a workspace from scripts:** `loupe session switch SESSION_ID --to
  shared|isolated` does what the chat's `/workspace` command does, from
  another terminal or a script. Switching to shared needs exactly one of
  `--publish`, `--hold`, `--export`, `--retain` or `--discard`; switching to
  isolated accepts `--approve-secret PATH`. `--switch-intent-id` makes a retry
  return the recorded switch instead of repeating it, and an interrupted
  switch can be confirmed or rolled back. Retryable refusals keep exit code
  75. See [switching from scripts](../isolated-workspaces.md#switch-from-scripts-or-another-terminal).
- **Higher isolated admission limits, not yet usable above 20,000 paths:**
  the isolated-mode defaults rise from 20,000 to 50,000 source paths and from
  20,000 to 100,000 inventory entries. Both are settings,
  `isolated.source_max_paths` and `isolated.hydration_max_entries`, up to
  100,000 each, and a refusal names the setting that applies. Restart the
  daemon after changing them. Byte, depth, time and secret-screening limits
  are unchanged. **A separate fixed limit still stops checkouts above 20,000
  source paths; see the
  [known limit](#known-limit-above-20000-source-paths) below.** See
  [admission counts](../isolated-workspaces.md#admission-counts).
- **Outside edits to files read earlier:** while native file watchers are
  healthy, an outside edit is reported for any of up to 20,000 files a session
  has read, not only the latest 1,000. On the polling fallback or after lost
  watcher events, coverage starts from the latest 1,000 and Loupe tells the
  model so. Stale writes are still refused at publication either way. See
  [native file watchers](../file-watchers.md).
- **Isolated catch-up:** a large catch-up, such as after a branch switch, no
  longer makes other sessions' publications wait until it finishes; they run
  between its steps. A directory that outside work replaced with a file now
  arrives at the next safe point when the private copy is untouched, instead
  of being reported as a conflict.
- **Optional installer cache:** `[isolated.rebuild] cache = true` lets
  dependency rebuilds reuse downloaded artifacts between isolated worktrees,
  so a second open can rebuild without the network. The cache is private to
  the profile, capped at 512 MiB by default, and unreadable by model commands,
  background processes and checks. Use it only with installers that verify
  lockfile hashes, such as `uv sync --frozen` and `npm ci`. With the cache on,
  checks need a working command sandbox. `loupe workspace cache prune` trims
  it and `--all` clears it. **The cache is off by default.** See
  [private installer cache](../isolated-workspaces.md#private-installer-cache).

## Known limit above 20,000 source paths

A checkout with more than 20,000 source paths (tracked files, plus untracked
files that are not ignored) stops accepting work soon after it starts. This
applies to shared and isolated mode alike:

- The first tasks run, and isolated mode now admits the checkout.
- Once the daemon lets go of the checkout, which it does after about 30 idle
  seconds, or restarts, every task there is refused with
  `CHECKOUT_FOREIGN_RECOVERY_REQUIRED` and the message `source checkpoint
  exceeds its 20000-path limit`.
- Nothing is lost or overwritten. Work resumes when the checkout is back at
  20,000 source paths or fewer. Until then, unpublished work in a private
  worktree stays where it is.

The cause is a check Loupe makes each time it takes a checkout back: it
re-observes every source path within a fixed 20,000-path budget, which the new
admission limits did not raise. The same budget makes `loupe workspace
cutover` refuse these checkouts. For shared mode this limit is not new in
0.1.0a4. **Keep checkouts at 20,000 source paths or fewer** until a later
release lifts it.

## Unchanged defaults

- **Cutover stays explicit.** Installing 0.1.0a4 changes no checkout's regime.
  See [the cutover guide](../workspace-cutover.md).
- **Independent review remains off by default.** On eight natural tasks,
  hidden checks passed 21 of 24 runs with review off and 21 of 24 with it on,
  for about 31% more tokens. See the
  [experiment](../experiments/natural-review-b7-2026-10-30.md).
- **Lexical indexing remains off by default, and there is no semantic
  search.** An offline comparison of embedding retrieval was inconclusive, so
  embeddings stay out. See the
  [experiment](../experiments/semantic-retrieval-f5-2026-10-30.md).
- **Filesystem limits** for managed operations are the same as in 0.1.0a3.

## Release verification

Before this release, a profile built with the unmodified 0.1.0a3 source was
opened in place with this version: two shared conversations with a published
change and a held proposal, and an open isolated conversation. Migrations
applied and the database passed its integrity checks. The old history and
proposal stayed readable, the proposal and both published changes exported
and the proposal applied. Both old conversations then ran new tasks, the
isolated one after receiving the other's changes and an outside edit. The
checkout stayed in the legacy regime. The steps are in
[`tests/fixtures/upgrade_0_1_0a3`](../../tests/fixtures/upgrade_0_1_0a3/README.md).
The test suite also upgrades a stored 0.1.0a2 profile straight to this
version.

The release workflow builds native Apple Silicon and Intel macOS bundles. After
the reviewed commit is tagged, the tap workflow verifies an upgrade from
0.1.0a3 on both architectures before advancing its formula. Tag publication is
a separate maintainer action; these notes do not claim that step has run.
