# Loupe 0.1.0a3

This prerelease brings Waves 1–11 to Homebrew installations: safer parallel
editing, isolated workspaces that a conversation can move into and out of,
managed background processes, native file watching, Git-aware publication,
optional review and project search, and explicit migration from legacy claims
to workspace execution.

## Before upgrading

Finish active tasks, exit open Loupe terminals, and **stop every profile's old
daemon before upgrading**:

```sh
loupe daemon stop
loupe --profile NAME daemon stop
HOMEBREW_NO_INSTALL_CLEANUP=1 brew update
HOMEBREW_NO_INSTALL_CLEANUP=1 brew upgrade loupe
```

Repeat the stop command for each profile you use. A daemon-unavailable message
means that profile is already stopped. Daemons from versions before the
cross-profile authority change do not honor the new physical checkout lock.
Running old and new daemons against one checkout can bypass that protection.
Homebrew cleanup can also remove an interpreter that an old daemon still uses.
The next conversation starts the upgraded daemon.

Back up profile data first if you need a rollback point. 0.1.0a2 has no
`loupe db backup` command, so copy the data directories after the daemons stop
and before upgrading:

```sh
cp -Rp ~/.local/share/llm-coord ~/llm-coord-data-0.1.0a2
cp -Rp ~/.local/state/llm-coord ~/llm-coord-state-0.1.0a2
```

These are the default locations; use your `XDG_DATA_HOME`/`XDG_STATE_HOME` or
`LLM_COORD_DATA_HOME`/`LLM_COORD_STATE_HOME` directories if you set them. The
copies contain session history and resume secrets; keep them private. Databases
migrate on startup; this release tests a real 0.1.0a2 profile with session/task
history, a published batch and a held proposal. Existing history and proposals
remain inspectable. Do not reopen an upgraded profile with an older binary.

## What changes

- **Parallel editing and review proposals:** held `/apply` merges changes onto
  current source and reruns required checks. Base checks protect deletion and
  undo. Other sessions' publications and outside edits reach coordination
  notices; advisory intent helps agents see overlapping work.
- **Isolated conversations:** `--workspace isolated` gives each conversation a
  private Git worktree with the checkout's current source. Supported ignored
  dependency trees can be copied privately or rebuilt through explicitly
  configured, sandboxed installers. Safe-point source/runtime refresh retains
  private edits and reports conflicts. Commands and checks redact actual copied
  private credential values. Closing removes private state once running work
  and retained proposals release it. Outside changes of any size, such as a
  branch switch or a large lockfile update, reach the private worktree. See
  [isolated workspaces](../isolated-workspaces.md).
- **Switching a conversation's workspace:** between tasks, `/workspace
  isolated` and `/workspace shared` move a conversation without losing its
  history. Unpublished private work needs an explicit choice: publish it, keep
  it as a proposal, export a patch, keep the worktree, or discard it. Conflicts
  block the switch. See [changing a conversation's workspace](../isolated-workspaces.md#change-a-conversations-workspace).
- **Background processes:** in isolated conversations, agents can start a
  long-running process such as a dev server or test watcher, read its screened
  output, and stop it. Command approval, sandbox, network and environment rules
  apply. Closing the conversation stops its processes, and switching workspaces
  is refused until they stop. Shared conversations refuse process starts. See
  [managed background processes](../isolated-workspaces.md#managed-background-processes).
- **Runtime export:** `loupe workspace runtime export PATH --session ID --to
  DEST` copies a private file or directory, such as a generated `.env` or build
  output, out of an isolated workspace. It previews first and needs `--yes`;
  likely secrets also need `--allow-secret`.
- **Native file watching:** FSEvents tells Loupe which files may have changed,
  so isolated safe points and outside-edit checks reread only those files. A
  20,000-file isolated safe point drops from about 2 seconds to under a quarter
  of a second. Loupe still verifies what it reads, and rescans fully at least
  every five minutes or when events may have been lost; after lost events, each
  session on the checkout is told to re-read files. Watching is on by default;
  `[workspace] watchers = "off"` keeps periodic full scans. See
  [native file watchers](../file-watchers.md).
- **Git-aware publication:** publication, `/apply` and `/undo` stop with a
  retryable error (exit code 75) while a rebase, merge, cherry-pick, revert or
  `index.lock` is in progress, and always for paths with unresolved index
  conflicts. Staged paths get a notice; `[core] refuse_staged_paths = true`
  refuses them instead. Committing your own edits is no longer reported as a
  branch switch. See [Git publication safety](../git-publication-safety.md).
- **Command environments:** the default minimal environment remains available;
  opt-in session environments carry approved project variables and translate
  checkout paths into command/check snapshots. Credential names and URL
  passwords are screened before forwarding.
- **Optional independent review:** a separate read-only reviewer can return
  findings before publication. A malformed finding no longer discards valid
  ones; an unfinished optional review produces a notice while normal checked
  publication can proceed. `/usage` includes review and exploration usage.
  **Independent review remains off by default.**
- **Optional project search:** explicit local lexical indexing and deterministic
  code-graph queries support project discovery. Optional agent retrieval is
  available for indexed projects; experiment records describe its limits.
  **Lexical indexing remains off by default.** See [optional retrieval](../optional-retrieval.md).
- **Operations:** `loupe db backup` creates verified private profile snapshots;
  `loupe db prune` previews and prunes eligible settled output. `loupe config
  show` explains effective configuration, and `loupe config set` validates saved
  changes. MCP transport/resources/prompts and helper approval notices are
  more complete. `loupe workspace authority status` and `prune` inspect and
  remove ownership records for checkouts that no longer exist; `prune` is a dry
  run until `--apply`. Isolated synchronization history stays bounded as a
  workspace grows.
- **One cooperating publisher per physical checkout:** profiles retain separate
  credentials/history and coordinate publication through an account-wide
  physical lock. Another profile can inspect and observe while ownership is
  held. See [cross-profile authority](../cross-profile-authority.md).

## Cutover stays explicit

**Installing 0.1.0a3 leaves every checkout in the legacy claim-backed regime.**
It does not cancel tasks, remove history, change Git refs, or automatically
convert editing authority. Review `loupe workspace cutover plan .` before an
explicit `loupe workspace cutover apply . --checkpoint CHECKPOINT`. Cutover is
irreversible and must include every participating profile's upgraded writers.
If a saved intent stops because another profile owned the checkout or retained
history changed, `loupe workspace cutover recovery` shows what changed and
`resume --accept-current-history` continues after you acknowledge it. See
[the cutover guide](../workspace-cutover.md) for dispositions and recovery.

## Filesystem limits

Managed operations require verified local filesystem semantics for the account
authority root, checkout, Git administration directory and common Git store.
Supported names are `apfs`, `hfs`, `ext2`, `ext3`, `ext4`, `xfs`, `btrfs`, `zfs`,
`tmpfs` and `overlay`. Other names fail closed, including `9p`/`drvfs` (such as
WSL `/mnt/c`), `virtiofs`, `exfat`, `ecryptfs` and FUSE filesystems. Keep these
locations on supported storage; environment variables cannot redirect the
account authority root. Refusals identify the detected filesystem. Read-only
status and doctor remain available to diagnose the refusal.

## Release verification

The release workflow builds native Apple Silicon and Intel macOS bundles. After
the reviewed commit is tagged, the tap workflow verifies an upgrade from
0.1.0a2 on both architectures before advancing its formula. Tag publication is
a separate maintainer action; these notes do not claim that step has run.
